# Microsoft 邮箱别名 Actions 设计

## 目标

将 `open_microsoft_email.py` 封装为可独立提交到 GitHub 的 GitHub Actions 项目。每个矩阵任务只处理一个主邮箱，单次最多 256 个任务，最大并发 20；只有 01/02 两个别名都被页面确认后才消费主邮箱记录。

## 输入与输出

仓库根目录 `verified_email.txt` 每行使用 `邮箱----密码----client_id----令牌`。工作流输入 `绑定辅助邮箱` 使用同样四段格式；非空时优先使用该凭据，空时在 credentialaction 分支从根目录 `辅助邮箱.txt` 随机选一条有效记录。输入只通过环境变量传递并立即脱敏。

成功汇总文件 `成功账号.txt` 以一个账号四行为单位：

```text
辅邮：辅助邮箱地址
主邮：主邮箱地址
子邮1：主邮箱前缀01@域名
子邮2：主邮箱前缀02@域名
```

成功结果不在 Actions 日志或 Summary 打印密码、client_id、令牌或完整凭据行。失败、超时、损坏 Artifact 和验证不完整的主邮箱保留在池中。

## 架构

`prepare` 校验邮箱池、任务数和并发值，输出一基矩阵索引。`register` 使用 `fail-fast: false` 的矩阵，每个 job 只调用一次单账号运行器；运行器内部最多三次独立浏览器尝试、每次独立 profile，并始终上传脱敏结果 Artifact。`collect` 使用 `if: always()` 下载 Artifact，从远端最新分支重算幂等结果，原子追加成功账号并删除已确认主邮箱，推送冲突时最多重试三次。

浏览器流程复用现有 Microsoft 页面选择器、credentialaction 辅邮验证、六位验证码逐框输入（框间隔 0.5 秒、`clear=False`）和每秒 `#id__0`/`Yes` 监听。Graph 取件失败回退模式 4 O2。Actions 使用直连网络，不配置代理；静态 HTTP 缓存与身份 profile 分离。

## 验证

离线测试覆盖四字段解析、256/20 上限、矩阵唯一分配、辅助凭据覆盖、Graph/O2 取件、三次隔离尝试、结果校验/幂等回写和 YAML 契约。测试不访问真实邮箱或浏览器，测试数据不含真实凭据。
